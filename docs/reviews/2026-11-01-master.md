## Summary
The change scaffolds the `nile-lab` reconciler: a Typer CLI with `validate` and `plan`, a pure planner, read-only host and Docker adapters, a provisional pydantic config, and a golden-output test suite. It meets the spec's "Done when" and AC-1 to AC-5. `uv run pytest -q` gives 99 passed. The layering rule holds (only `adapters/` does I/O, and the planner is pure). There is no Cloudflare or write code yet, so none of the lab boundaries (nova, Authentik, owned-only deletes) can be violated by this change. The findings below are robustness gaps and hygiene items, none blocking.

## Minor
### 🟡 Docker failures surface as a traceback, `src/nile_lab/adapters/docker.py:19-26`, `src/nile_lab/cli.py:75`
**Problem**: `available()` only checks that the `docker` binary exists. If the daemon is down (e.g. early in boot) or the binary vanishes, `_run` raises `DockerError` (or an uncaught `FileNotFoundError`), and `cli.plan` does not catch it. The user gets a Python traceback. `subprocess.run` also has no timeout, so a hung daemon hangs `plan`.
**Why it matters**: The spec's CLI contract is exit `1` for a runtime error with a clear message. Feature 4 will install Docker, so this path becomes reachable soon, and the boot flow runs right after `docker.service`.
**Suggested fix**: Catch `DockerError` (and `OSError`) in the CLI and print one line with exit `1`, or have `observe` treat an unreachable daemon as `docker_available=False` with a note. Add a timeout to the subprocess calls. Add a test.

### 🟡 `read_routes` can raise on unexpected `ip` output, `src/nile_lab/adapters/host.py:424-428`
**Problem**: Failures of `ip` are swallowed and return `()`, but a `json.loads` error on bad output is not caught. More importantly, a failed `ip` silently disables the subnet-overlap refusal (a safety check) with no signal in the plan.
**Why it matters**: The overlap guard protects the `nova` routes and the host. It should not fail open silently.
**Suggested fix**: Distinguish "no routes" from "could not read routes". Surface a note, or a refusal in apply, when the read fails.

### 🟡 Container name matching assumes the project name, `src/nile_lab/planner.py:149-154`
**Problem**: Containers are looked up by `nile-<client>` (the compose project name). Compose normally names containers `<project>-<service>-<n>` unless `container_name` is set. The spec does not fix this. Today it only works against fixtures.
**Why it matters**: Once feature 5 generates compose files, every client could read as absent and be planned for `create` again, which breaks the "reruns are noop" invariant. The `docker ps --filter name=^nile-` and the label-based ownership still work, but the join does not.
**Suggested fix**: Join on the `lab.nile.client` label (already in the ownership contract), or record the `container_name` decision in the spec before feature 5.

### 🟡 Unit file discovery is shallow, `src/nile_lab/adapters/host.py:435-440`
**Problem**: `glob("nile-lab-*")` also matches directories such as `nile-lab-boot.service.d`, which read as `managed=False` and get reported as foreign. Symlinked and `.wants` entries are not considered. udev rules (`90-nile-lab-*.rules`) from the ownership contract are not observed yet.
**Why it matters**: Spurious "foreign" noise, and a later phase could misjudge ownership.
**Suggested fix**: Limit to regular files, handle drop-in directories explicitly, and add the udev directory when the host phase is built.

### 🟡 Label parsing breaks on commas in values, `src/nile_lab/adapters/docker.py:329-338`
**Problem**: `docker ps` gives labels as `k=v,k=v`, so a value containing a comma is cut and later labels can be mangled. Current owned labels have no commas, but third-party containers' labels are parsed too.
**Why it matters**: Low risk now (it cannot make a foreign container look owned unless it has `lab.nile.managed=true`), but fragile.
**Suggested fix**: Use `docker inspect` for label data (already done for networks), or document the limit.

### 🟡 Secrets-handling gaps in repo hygiene, `.gitignore`
**Problem**: `.gitignore` covers only Python artifacts. Nothing guards a real `lab.yaml`, `*.token`, or `.env` that someone might copy into the repo during development (`sudo uv run nile-lab` from the repo is an advertised workflow). Also, the first commit will include `requiremetns.txt` (misspelled), which is the original brief and is not product code. `test-preferences.json` is untracked tooling config.
**Why it matters**: The spec's key invariant is that secrets live only in `lab.yaml`. One accidental `git add` leaks the Cloudflare token.
**Suggested fix**: Add `lab.yaml`, `*.token`, `.env*` to `.gitignore` (keep `examples/`). Move or rename the brief (for example `docs/brief.md`) before the first commit, and decide whether `test-preferences.json` is committed.

## Strengths
- The planner is genuinely pure, with ownership checked in one place. Unowned networks, containers and units are reported as `foreign, ignored` and never get an action (AC-4).
- Config errors never echo input values, using `include_input=False` plus `SecretStr`, and the tests assert the token is absent. The root check runs before the config is read.
- The golden text and JSON fixtures, the fake-observe fixture, and tests that read real-shaped sysfs trees make the suite fast and root-free.
- Refusals outrank pending changes in the exit code, and the overlap check correctly excuses the tool's own bridge route.

## Test coverage
Good for a scaffold: 99 unit tests pass. Planner cases (create, noop, recreate on a moved link, stopped start, claimed dongle fallback, orphan, foreign, overlap refusal), CLI exit codes and golden output, config validation, host sysfs parsing and the Docker adapter parsing are covered, with `# covers: AC-n` tags. Gaps: no test for the Docker daemon-down or `ip` failure paths (see first two minors), no test for `/31` and `/32` mgmt subnets (they do produce a clean `ConfigError` today, verified manually), and no test for directory entries in the unit dir.
